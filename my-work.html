The DCU under test

Cameras and radars feed two zonal ECUs, which feed the DCU, which drives the vehicle outputs.

02 — Input files

Client files and where each one goes

I engage the client for the input files, then validate every file on receipt before project execution starts.

03 — Hardware

Pre-flight hardware gate

Three paths are checked before any flashing or test run: debug, CAN and power. The bench is only ready when all three pass.

04 — Bench

Bench wiring

The laptop reaches the ECU through two paths: Trace32 over JTAG for debug, and CAN Case XL over the harness for CAN. A separate supply powers the harness.

05 — Environment creation

A simulation for camera and radar inputs

Built in CANoe so the DCU can be validated without the vehicle around it. Six steps, in order.

06 — Smoke testing

Eight smoke checks in four phases

A fast health check of the DCU before deeper test execution. Each check gates the next.

07 — Achieving Zero DTC

From faults to a Zero DTC environment

Read the DTCs, and if any remain, trace each one to its signal, apply the recovery and read again until the count is zero.

08 — Failsafe test execution

Example: camera blockage

Requirements are filtered by vehicle type (HEV, EV or Normal), turned into VTESTstudio scripts, imported into CANoe and run with controlled voltage, variant code and vehicle speed.

09 — Test report

Review, comment and publish

Any comment sends the work back to re-test and regenerate the report. Only an approved report is published to Jira, with its pass, fail and not-applicable totals.

10 — Conclusion

Challenges in system testing

What makes this work demanding, and how I plan around it.

ECU hardware limits

Customer hardware versions can differ from what is on the bench; a lower-version setup may not give accurate results.

Flashing risks

Power interruptions or the wrong file can leave an ECU unusable or "bricked".

Complex setup

JTAG connectors, Trace32 and harness cables must all be in proper condition.

Zero DTC accuracy

No false positives or negatives during DTC checks.

Test volume

Large numbers of test cases across vehicle types and conditions.

Intermittent failures

Some faults do not reproduce consistently, so they are harder to diagnose.
